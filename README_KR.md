## ClassCard Security Research
2026-02-24 ClassCard의 계정 복구 기능을 분석하던 중 다음 두 취약점을 발견했습니다.

1. 아이디 찾기 기능의 이메일 소유권 검증 미흡
2. 예측 가능한 비밀번호 재설정 토큰

두 취약점을 연계할 경우 타인의 아이디를 획득한 뒤 비밀번호 재설정 토큰을 예측하여 계정 탈취가 가능했습니다.

## 취약점 상세 내용
### 1. 아이디 찾기 기능의 이메일 소유권 검증 미흡
아이디 찾기 기능에서 `user_idx`와 이메일 주소 사이의 소유 관계가 충분히 검증되지 않았습니다.

**Request**:
```
POST https://www.classcard.net/LoginProc/sendIDToContact HTTP/1.1
Content-Type: application/x-www-form-urlencoded; charset=UTF-8
sel_user_idx=인덱스&str_contact=이메일&find_by=email
```

**Response**:
```
HTTP/1.1 200 OK
Content-Type: text/html; charset=UTF-8

{"result":"ok","msg":"","sendID":4}
```

`sel_user_idx`에 대상 사용자의 값을 지정하고 `str_contact`에 공격자가 접근 가능한 이메일 주소를 입력했을 때, 대상 사용자의 아이디가 해당 이메일 주소로 실제로 발송되는 것을 확인했습니다.

즉, 입력한 이메일 주소가 대상 계정에 등록된 이메일 주소인지 확인하지 않고 아이디 발송 대상으로 사용되고 있었습니다.

### 2. 예측 가능한 비밀번호 재설정 토큰
비밀번호 재설정 토큰을 분석한 결과, 암호학적으로 안전한 난수가 아닌 순차적으로 증가하는 숫자를 Base64로 인코딩한 값이 사용되고 있었습니다.

예를 들어 다음과 같은 토큰을 확인했습니다.
```
OTQ0OTQ0 > 944944
OTQ0OTQ1 > 944945
```
내부 값은 다음과 같이 순차적으로 증가했습니다.
```
944944
944945
944946
...
```
또한 해당 값은 계정별로 독립적으로 관리되는 것이 아니라 서비스 전체 비밀번호 재설정 요청에 공통으로 적용되는 전역 시퀀스였습니다.
따라서 공격자는 자신의 계정에서 정상적으로 비밀번호 재설정 토큰을 발급받는 것만으로 현재 시퀀스 값을 확인할 수 있었습니다.
이후 대상 계정에 비밀번호 재설정 요청을 하면 다음 시퀀스 값을 기반으로 생성되는 토큰을 예측할 수 있었습니다.

## 계정 탈취
두 취약점을 다음과 같이 연계할 수 있었습니다.

1. 아이디 찾기 기능의 검증 문제를 이용해 대상 사용자의 아이디를 공격자가 지정한 이메일 주소로 수신합니다.
2. 공격자 자신의 계정에서 비밀번호 재설정 요청을 수행합니다.
3. 발급된 토큰을 통해 현재 사용 중인 전역 시퀀스 값을 확인합니다.
4. 대상 사용자의 아이디로 비밀번호 재설정을 요청합니다.
5. 다음 시퀀스 값을 계산하여 대상 계정에 생성된 비밀번호 재설정 토큰을 예측합니다.
6. 예측한 토큰을 비밀번호 재설정 과정에 사용합니다.

예측한 토큰을 실제 비밀번호 재설정 과정에서 사용했을 때, 대상 사용자의 기존 비밀번호를 알지 못한 상태에서 새로운 비밀번호로 변경되는 것을 확인했습니다.
최종적으로 대상 계정에 비인가 접근이 가능했습니다.

현재는 패치가 완료된 상태이며, 서비스 운영 측의 공개 허가를 받아 포트폴리오 목적으로 작성했습니다.
